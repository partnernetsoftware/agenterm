## 0. 为什么这是枢纽问题

架构已定：N 份极小的原生内核（四原语：内存/跳转/可达/调用；不封装）+ ISA/OS 中立的载荷。
但**中立 IR 的前提是必须有东西把 IR 降级成原生码**。Q0 的层数实验里载荷是**预先编译好的原生
blob**，内核只 map+jump——**根本没有降级器**。所以那个「TCB 仅 2.7KB」量的是**一个跑不了中立
IR 的内核**。

真正决定「极致微小」活不活的枢纽因此是：

> **最小可用的 IR→原生码降级器有多大（记为 X 字节）？它该放核内还是核外？**

- **核内** → 冻结的内核从 ~2.7KB 涨到 ~2.7KB+X。**X 从没人量过。** 且每 ISA 一份，N 的成本立刻重要。
- **核外** → 内核保持最小（TCB 最优），但每个 ISA 要发一份降级器载荷，**总交付可能反而更大**。

这正是「最小的核」与「最小的总交付」两个**不同**的最优解，现在有了可测形式：**X = 最小可用降级器的字节数。**

### 已确定、不在本实验讨论范围内的事

1. **中立 IR 是否真能中立地降级到两个不兼容 ABI**——那是 Q1 的问题（`ir/`）。本实验**假定** IR
   已给定并聚焦「降级器多大、放哪」。本实验只做 x86_64 一个 ISA，OS 侧 Windows 真跑、Linux 交叉量字节。
2. **降级器只为它自己所在的机器生成代码。** 交叉编译是把字节写进文件，是普通载荷能力，不是降级器能力。
3. **四原语不变。** 降级器是原语 ①（内存 RW→RX）+ ②（跳转）的**使用者**，不是第五类原语。
   它把 IR 写成机器码字节 → `mem_protect(RX)` → 跳入。若发现降级器逼着往内核加第五类原语，**如实记录，不偷加**。

## 1. 硬约束（违反则实验无效）

### 1.1 降级器只是原语 ①② 的使用者

降级器**不得**扩充内核原语集。它只能：把 IR 解析成 x86_64 字节、向 ① 要 RW 内存、写字节、
`mem_protect` 翻 RX、把控制权交给它（②）。**产生新代码并执行**正是 ①+② 的完备性论证所承诺的能力
（见 Q0 §1.1）。降级器就是那句承诺的兑现物。

### 1.2 「最小可用」的定义（本实验的核心裁量，事前钉死）

降级器**必须能真正跑通那三个既有载荷的语义**（`pure_compute` / `read_hash_print` / `spawn_echo`），
输出与 Q0 的原生 blob **逐位一致**（哈希 `a49d2cbecc13994f`；pure exit=163；spawn 打印 `exit=07` 且退出码 7）。
**不能是玩具。** 在此前提下取最小，判据是：

- 只覆盖**整数/指针字子集**（无浮点、无结构体传值、无值返回聚合）——与 Q0 ④ `call` 原语的子集**对齐**，不扩大。
- **固定 vreg→物理寄存器映射，无寄存器分配器**、无优化 pass、无 IR 语法糖、无 SSA。
- IR 是一个**朴素寄存器机字节码**（§2 定义）。降级器是**单遍发射 + 一遍回填跳转**，不做别的。
- **本实验测的是「最小可用」的字节数，不是一个好编译器。** §4 的失败模式警告专门盯这一条：
  **任何为代码质量/生成码效率把降级器做大的冲动，都是本实验要检测的病，不是要满足的需求。**

**被降级的是什么**：Q0 的 blob = `payloads/*/logic.rs`（载荷逻辑）+ `adapters/*`（OS 可达性胶水）
+ `abi.rs`，全部由 rustc 提前编成原生码。本实验**只把 `logic.rs` 那一层（载荷逻辑：算术/循环/
访存/哈希/格式化/分支/调用）改由运行时降级器从 IR 产出**；`adapters/*` 与内核保持 Q0 原样的原生可达性
substrate（降级出的代码通过一张 env 函数表调用它们）。理由：**OS 可达性的中立性是 Q1 的问题，不是 Q3 的**；
Q3 要量的是 codegen 本身。载荷的**独特语义**（100 万次乘加循环、逐字节 FNV-1a、十六进制/十进制格式化、
条件退出码、字节 load/store、循环与分支）全部走 IR、全部在运行时降级——这足以证明「非玩具」。

### 1.3 两种打包共用同一份降级器实现

**不写两个降级器。** 写一份，打包两次（沿用 Q0 变体思路，度量口径必须与 Q0 一致，否则不可比）：

- **核内（in-kernel）**：降级器静态链进内核产物（=Q0 变体 A 风格的单产物）。载荷 = IR 字节。TCB = 内核+降级器。
- **核外（out-of-kernel）**：内核保持 Q0 的最小四原语 loader；降级器编成一个 flat blob，由内核 `load_and_run`
  加载（=Q0 变体 B 风格），blob 再消费 IR、发射并跳入载荷码（**双段 mmap+jump**）。TCB = 仅最小内核。

**已知偏差（须在报告复述）**：两种打包都用 rustc 把降级器源码编成原生码，故 X 是「最小可用降级器成本的
上界」——手写汇编的降级器可能更小。上界足够决策，但结论不得写成「核外一定更大/核内一定不可行」的绝对判断。

### 1.4 不许把降级器越做越大去追求代码质量

任何形如「加一个窥孔优化 / 加浮点 / 加真正的寄存器分配 / 加 IR 宏展开」的冲动，**都等于偏离本实验**。
真觉得缺，**记为发现（判据②的备注），不要偷偷加进被测降级器**。

## 2. 最小实验：一个 ISA、一份 IR、两种打包

| 维度 | 选择 | 理由 |
|------|------|------|
| **ISA** | 只做 x86_64 | 时间盒；ISA 轴的成本靠判据②的「共享 vs ISA 专属」拆分来投影，不实际做第二个 ISA |
| **OS** | Windows 真跑；Linux 交叉编译只量字节 | 沿用 Q0（本机无 WSL）。降级器本身 OS-无关；OS 差异在 adapters/IR 数据里，不在降级器里 |
| **IR** | 朴素寄存器机字节码（下表），本实验自定义 | 满足 §1.2；能表达三载荷的独特语义 |
| **载荷** | 复用 Q0 那三个的语义，**不新造** | 与 Q0 数字连续可比；第三个（spawn）是已知硬骨头 |

### IR 形状（寄存器机，16 个 vreg；固定映射，无分配器）

字节码：每条 = 1 字节 opcode + 定长操作数。vreg 0..3 映射到 x86 **被调用者保存**寄存器
（rbx/r12/r13/r14，跨 call 存活）；vreg 4..12 映射到调用者保存寄存器（rax/rcx/rdx/rsi/rdi/r8/r9/r10/r11，
call 后不保证）；**r15 保留为 env 表指针**（入口从 rdi 拷入）。

| opcode | 语义 | 覆盖谁 |
|--------|------|--------|
| `IMM rd, imm64` | rd = 常量 | 全部 |
| `MOV rd, rs` / `ADD/SUB/MUL/AND/OR/XOR rd, rs` | 算术/逻辑（MUL=imul） | 全部（FNV 乘加、掩码、异或） |
| `SHL/SHR rd, imm8` | 移位 | rhp 的 hex 提取 |
| `LD8/LD64 rd, [rb+off]` / `ST8/ST64 [rb+off], rs` | 访存（字节 & 字） | rhp/spawn 的缓冲读写、格式化 |
| `JMP L` / `JB/JAE/JE/JNE ra, rb, L` | 无条件/有条件跳转（回填 rel32） | 循环与分支 |
| `LABEL L` | 跳转目标锚点 | 控制流 |
| `CALL rd, idx, argc, [a0..]` | 调 env 表第 idx 项（sysv64，≤6 字参），结果入 rd | mem_alloc / read_file / write_stdout / spawn_wait / exit |

env 表（由「runner」在原生侧构造，降级出的码通过它够到 substrate；这不是新原语，是 ④ `call` 的同构用法）：

```
[0] k 指针（数据）   [1] mem_alloc   [2] read_file(k,path,buf,cap)
[3] write_stdout(k,buf,len)   [4] spawn_wait(k)   [5] exit(code)   [6] path "input.txt\0"
```

`mem_alloc`/`exit` 是内核原语本身；`read_file`/`write_stdout`/`spawn_wait` 是 Q0 既有 adapters 的地址
（OS 可达性 substrate，原样复用）。**降级器不认识 OS——它只认识 IR 与 x86_64。**

## 3. 判据（**动手前认，事后不得改**）

沿用任务方建议的四条，我按本实验裁量补了度量方法与阈值，理由写在每条备注里。

| # | 判据 | 度量方法 | 性质 |
|---|------|----------|------|
| **①** | **最小可用降级器的字节数 X** | 降级器编成独立 flat blob 的字节数（strip 后 release），并用「核内产物 − 无降级器基线内核」交叉核对 | **核心（截距）** |
| **②** | **共享 vs ISA 专属拆分** | 降级器源码切成两块：**ISA-无关**（IR 解析/控制流/回填/env 调用策略/vreg 映射表）与 **x86_64 专属**（指令编码器 `emit_*`）。报**行数**（精确）与**字节**（按函数隔离估算，注明只建了一个 ISA）。**专属块 = 每加一个 ISA 要复制的量** | **斜率（决定性）** |
| **③** | **核内 vs 核外两种打包的总交付** | 沿用 Q0 口径（x86_64；strip release 字节；同工具链/flag）。对「机器上服务 M 个载荷」给出总交付公式并代入 M=3 | 截距 |
| **④** | **核内方案的 TCB 涨到多少** | 核内产物里「必须被信任」的字节 = 内核+降级器；与 Q0 的 ~2.7KB(L)/~3.4KB(W) 对照 | 安全 |

### 度量纪律（与 Q0 一致，换了就不可比）

- 字节数一律取 **strip 后 release**；编译器/flag 沿用 Q0 的 `build_*`（`-O -C panic=abort -C debuginfo=0` 等）。
- ② 的行数不含测试与文档。
- Windows 真跑并核对输出；Linux 交叉编译只量字节（本机无 WSL，与 Q0 同处理，诚实区分）。
- 每个数字第三方可复跑，命令写进本文件 §8 与 `research/dynamic-core/lowering/`。

### 为什么把 ① 定为「独立 blob 字节数」而非「源码行数」

任务明确要求「**字节数**（不是行数）」。独立 blob 是 X 最干净的隔离测量（只有降级器机器码，
不含 adapters/IR/内核）；核内 delta 作交叉核对。行数只在 ② 的拆分里用（因为「共享 vs 专属」是源码结构问题）。

## 4. 判决规则与 kill criterion（事前写死）

主命题是「**最小的核 vs 最小的总交付**」这对取舍能否被 X 一锤定音。

1. **先看 ③（总交付）是否在两种打包间分出胜负。**
   - 若核外总交付明显 > 核内（因为降级器要额外发一份 blob 且不能摊薄）→ 判**核内**。
   - 若两者打平（降级器无论放哪都得发一份、字节相近）→ ③ 不决定，落 ④。
2. **③ 打平 → 看 ④（TCB）与 ①（X 相对内核基线的比例）。** 若 X 相对 ~2.7KB 内核**小到可忽略**
   （比如 <25%），核内几乎不涨 TCB，偏**核内**；若 X **可观**（与内核同数量级或更大），核内使冻结内核
   TCB 翻倍以上，偏**核外**（保住「最小的核」）。**阈值 25% 事前钉死。**
3. **看 ②（斜率）做最终否决**：若降级器的 **x86 专属块**占比高且**随 ISA 数线性复制**，则「核内 × N 个
   ISA」是新的向外增长轴——此时即便单 ISA 下核内更省，也**偏核外**（把这份线性成本发成载荷，摊薄到用到的人）。
   这与 Q0「斜率 > 截距」的价值排序一致。**②否决权最高**（斜率优先于截距 ①③④）。

### 判决树与 §3 优先级对账（照 decisive-experiment §3 做，避免「两种读法」陷阱）

- **每个判据都在树里**：① 在步 2（X/内核比例）、② 在步 3（否决权，最高）、③ 在步 1、④ 在步 2（TCB）。无遗漏。
- **性质排序**：② 是斜率、否决权最高；③①④ 是截距/安全，服从 ②。与「斜率>截距」一致。
- **诚实降级（关键偏差）**：本实验**只建一个 ISA**，故 ② **不是两点实测的斜率**，而是**单 ISA 的源码结构投影**
  （共享 vs x86 专属的行/字节拆分）。按 decisive-experiment「只做一个轴上的点=零信息量」的警告，**②的证据强度低于
  一个真·两点斜率**——它给方向，不给确值。若 ② 的方向与 ③④① 冲突且证据不足以否决，则如实报「两种读法」，不硬判。
4. **kill criterion**：若「最小可用」被证明**根本做不小**——即 X 大到让核内 TCB 涨过某个荒谬点
   （事前定：X > 8×内核基线，即 >~22KB），则结论直接是「核内不可行，降级器必须核外」，停，写结论。
5. **诚实条款**：若结论是「两种放法都差不多」或「降级器大到核内不可行」，**如实报——推翻预期价值更高**。
6. **时间盒**：量出 ①②③④ 即停。**不做第二个 ISA、不做优化、不做 IR 语法糖、不追代码质量。**

### 失败模式警告

这类探索最常见的死法：**把降级器越做越大去追求代码质量**，于是 X 失真、结论被污染。
本实验宁可要一个「丑但最小且能跑通三载荷」的降级器，也不要一个「漂亮但把 X 撑大」的。

## 7. 本实验**不**回答

- **IR 能否中立降级到两个不兼容 ABI**（Q1 `ir/`）。本实验的 adapters 复用 Q0 的 sysv64 桥接，不重测中立性。
- **第二层组合机制**（适配包如何可复用而不被钦定）。
- **可验证性/DDC**（同一 IR 经不同路径降级须行为等价）。本实验只做单降级器，不做双路径对拍。
- **多 ISA 下的真实斜率**——只投影，不实测第二个 ISA。

## 8. 实验结论回填（2026-08-08，实测）

实现落在 `research/dynamic-core/lowering/`。判据已于本节之前钉死，事后未改。复跑命令见
`research/dynamic-core/lowering/README.md`。

### 「最小可用」的最终定义（照 §1.2，实测达成）

一个**朴素寄存器机字节码**（`ir.rs`，24 个 opcode）的 **x86_64 单遍发射器 + 一遍 rel32 回填**
（`lower.rs`），整数/指针字子集，固定 vreg→物理寄存器映射，无优化、无寄存器分配器、无 IR 语法糖。
它是原语 ①（mem_alloc/mem_protect）与 ②（jump）的纯使用者。**已真正跑通三载荷、输出与 Q0 逐位一致，
且核内(A)与核外(B)两种打包在 Windows 上全部实测通过**（`pure` exit=163、`rhp` = `a49d2cbecc13994f`、
`spawn` 打印 `exit=07` 退出码 7；共 6 个产物）。**非玩具。** 未加第五类原语。

### 四个数字（strip 后 release；x86_64；rustc 1.97；Linux 交叉量字节、Windows 真跑）

`X/内核 = 3003/2932 = 102%`（核内跳转表版 95%），**远超 §4.2 事前钉死的 25% 阈值**。

### §4 判决树逐步走（规则事前写死）

1. **③（总交付）分出胜负？** 是——方向是**核外 > 核内 ~1.5KB（~20%）**（核外复制了 mem_intrinsics、吃 PIC 开销、
   还要单发一份内核）。按 §4.1「核外总交付明显>核内 → 判**核内**」，③ 指向**核内**。且 M 个载荷时差为恒定 ~1.5KB（两边每载荷只加 IR）。
2. **④（TCB）反向**：核内把冻结 TCB 从 ~2.9KB 抬到 ~6.2KB（≈翻倍），因为 **X≈内核大小**。④ 指向**核外**。
3. **②（斜率）不区分放置**：X 的 x86 专属块（~46%）**无论核内核外都随 ISA 数复制**（Q0 §0.2：内核本就每 ISA 一份，
   降级器 blob 也每 ISA 一份）。所以 ② 不是「核内 vs 核外」的判据；它量到的是**「有降级器」本身的新斜率**——
   codegen 让每 ISA 的原生足迹从 Q0 的 ~2.7KB **近乎翻倍**。这是 §3 认定最重要的「向外增长」，**首次量到，且与放置无关**。
4. **kill criterion**：`X=3003 < 8×内核(~23KB)` → 「核内不可行」**未触发**。核内在字节上完全可行。

### 判决：这是一个真·取舍，且实现时冒出一条规格外的决定性约束（现已量化+解决）

**②③④ 把天平钉成一个无免费午餐的取舍**，X≈内核大小正是它成为真取舍（而非显然）的原因：

- **要最小总交付 → 核内**（③：小 ~1.5KB 恒定；核外的双份 mem_intrinsics + PIC + 独立内核更贵）。
- **要最小冻结 TCB → 核外**（④：~2.9KB vs ~6.2KB；核内因 X 大而近乎翻倍）。

**且冒出一条 ①②③④ 之外、却带决定性的经验**（如实记，推翻预期价值最高）——**加重核内一侧**：

> **把「降级器」（一个代码生成器）当 flat 非重定位 blob 跑，会撞上 Q0 预编译载荷从未碰到的约束。**
> 最小内核的 `load_and_run` 只 copy+jump、**不施加任何重定位**。所以核外的降级器 blob 必须：
> (a) **无 memset 依赖**——大栈数组零初始化会发 `memset` 调用（flat blob 无法满足），已改为从原语 ① 申请
> scratch 规避；(b) **无跳转表**——dense 派发（`match` 或 if-else）编成 PC-relative 跳转表，展平复制后仍破
> （`llvm-objdump` 证实 emit 里有 `jmpq *%rcx`；加 `-C llvm-args=-min-jump-table-entries=200` 抑制后消失）。
> **两条都修好后，核外三载荷在 Windows 全部跑通**（B_pure=163、B_rhp=`a49d2cbecc13994f`、B_spawn exit=07/7）。
> **代价**：抑制跳转表使 X 从 2777→**3003 B**（+8%），且是一份**更脆的、须持续守 PIC-flat 洁净的降级器**。

即核外「保住最小内核」不是免费的——它把成本转移成「降级器必须 PIC-flat 洁净」（本实验实测约 +8% 字节 +
持续的脆性），或者让最小内核长出一个重定位器（内核变大，正好**侵蚀核外自己的 TCB 优势**）。核内（正常可重定位 PE）
无此约束，用跳转表更小更省事。

**净判决**：这是一个**真取舍，无免费午餐**：
- **按 §4 字面树（③ 领先）+ 这条 PIC-flat 约束 → 偏「核内」**（总交付小 ~1.5KB、运行最省事、降级器可用跳转表）。
- **若把「冻结 TCB 最小」当压倒性目标（④）→ 偏「核外」**，但须为 PIC-洁净降级器（+8%、更脆）或重定位内核买单。

决定性的意外是：**X 不小**（≈3KB≈整个内核），所以核内确实让 TCB 翻倍——**两边都不免费**。**未为让结论好看而改度量。**

### 未测的替代设计点（编排者 R1 综述插入，可能改变整个成本结构）

- **copy-and-patch stencil（CPython 3.13+ 已发货）**：构建期用真编译器产出机器码模板，运行时的降级器只剩
  **memcpy + 重定位应用器**（综述论证为 KB 级 Futamura 第一投影）。若成立，**X 的「代码」部分塌缩到几百字节**
  （核内 TCB 几乎不涨），而 ISA 专属成本移到**stencil 数据**（可当载荷发，核外形态）——**这会溶解上面的取舍**：
  小 applier 核内 + stencils 作数据。**本实验测的是手写编码器（X=3003 flat-safe / ~2777 in-kernel）；
  copy-and-patch 是一个数量级不同的点，未测。** 记为下一实验（Q?）的首要候选。
- **原语 ① 缺放置约束**：本降级器的相对跳转（rel32）**只在单个 ≤8KB 生成缓冲内**，远在 x86 `±2GB` 内，
  无静默截断风险（已确认）；`call` 走绝对地址（env 表间接），无范围问题。多 ISA 时 `CALL26 ±128MB` 需显式约束。
- **平台正在收回 RWX**：两种放置都依赖 `mem_alloc(RW)→mem_protect(RX)→jump`（原语 ①②），故
  Windows ACG / systemd `MemoryDenyWriteExecute` / iOS 无合法 JIT 路径**同等打击两者**——这不改变本实验的字节度量，
  但**任何推荐（尤其核内自我扩展）都须标注此前提风险**：无 RWX 时动态降级根本不成立，须退回预编译（=Q0）。

### 与规格不符之处（必然有）

1. **核外运行时的 flat-PIC 约束（实现期意外，已量化+已解决）**：核外变体初次运行时崩溃（`memset` 依赖 +
   跳转表在 flat 非重定位 blob 上破损）。用 `llvm-objdump` 定位到 emit 里的 `jmpq *%rcx` 跳转表；改为
   (a) 从原语 ① 申请 scratch 免 `memset`、(b) 构建加 `-min-jump-table-entries=200` 抑制跳转表，**核外三载荷
   随即在 Windows 全部跑通**（B_pure/B_rhp/B_spawn 与核内逐位一致）。此约束**不是偏差而是发现**——已并入判决
   （核外须 PIC-flat 洁净，实测代价 X +8% 且更脆）。两种打包**均已验证运行**（Windows），Linux 交叉量字节（无 WSL）。
2. **② 是单 ISA 投影，非两点斜率**（规格 §4 已声明）：只建 x86_64，「每 ISA 复制量」由源码行拆分投影，证据强度低于真两点。
3. **X 用 ELF flat 两blob相减度量**（Q0 blob 口径）：driver_flat 含 `abi` panic + mem_intrinsics（两半都有，抵消），
   故 X=lower−driver 隔离降级器自身机器码；含 ≤~20B 度量脚手架（black_box 使 IR 不透明以防 DCE 掉编码器）。
4. **被降级的只是载荷逻辑层**（Q0 的 `logic.rs`）：adapters/内核保持 Q0 原样原生 substrate（§1.2 已声明）。OS 可达性中立性是 Q1 的问题。
5. **④ `call` 子集沿用 Q0**：整数/指针字、≤11 参；本实验的 env 表调用同此模型，未扩大。
6. **未加第五类原语**：降级器纯用 ①②；§1.1 的「加第 5 条」冲动未出现。记为发现。
