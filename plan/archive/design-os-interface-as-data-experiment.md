## 0. 背景与已确定、不在本实验讨论范围内的事

Q1 与 Q4 两个独立实验撞到同一条缝：**这个架构只有一条缝，就是 OS 接口**。缝之上
（计算/控制流/内存）中立、可共享、可结构验证；缝之处（L1–L5）per-target、手写、不可验证。

**已确定、本实验不重开的前提**（编号列出）：

1. **2 层架构**（Q0 判决）。四原语 + 不封装纪律。
2. **ABI「摆放」半边可推迟**（Q1 非泄漏结论）：参数寄存器/影子空间/红区/返回寄存器
   全由语义签名推导，已实测跑通。本实验**不重测**这半边——它已经是数据（签名）驱动的。
3. **泄漏就是 OS 接口内容**（Q1）：本质三类 —— L1 符号名/系统调用号、L2 语义参数数→
   原生参数数映射与常量注入、L3 结构体布局（头号难点），外加 L4 出参宽度、L5 错误哨兵。
4. **结构性可验证止于中立核**（Q4）：intent 区 0 结构可验。Q7 若把 intent 区变成可校验的
   数据，就可能收窄这个洞——④ 量它。
5. **复用 Q1 的 IR、asm 编码器、三个载荷，逐字节不改**。Q7 只替换「Call 如何降级」这一路径。

## 1. 硬约束（违反则实验无效）

### 1.1 机制固定，能力靠数据

存在**一个固定的通用编组器（marshaller）**，它对所有 intent、所有目标是同一份代码。
一个 intent 的 OS 接口内容（reach、参数配方、常量注入、出参、布局）**只能表成它消费的数据**。
判定式：**编组器里不得出现 `match intent { … }` 之类的逐 intent 分支**。出现即视为「没变成数据，
只是把代码换了个地方」。

### 1.2 病灶探测器（本实验要检测的病）

任何为了覆盖某个泄漏而**给编组器加一个 intent 专属分支 / 发明一个调用时序小语言（call-sequencing
bytecode）/ 让数据表长成一份接口描述语言（IDL）**的冲动，是本实验要**检测**的病，不是要满足的
需求。真需要就**记为发现**（判据 ⑤），不要偷偷加。**最该警惕的失败模式：滑向发明一个 IDL/IR ——
那就是重演 WASI/CORBA/ANDF 的路，中立 OS 接口一旦变成规范就单向膨胀。**

> 一条**边界内的**例外，必须显式声明：**叶子数据引用**（一个名字解析成一个数：符号索引、
> 系统调用号、ctx 绑定索引、CO-RE 式字段偏移查询）**不是** IDL —— 它是 BTF/CO-RE 已验证
> work 的形态（R1 §4.1e），是一个**有界**的重定位种类集（字段偏移/存在/尺寸/位域）。
> 而**调用时序 + 控制流 + 数据流编排**（fork/分支、取句柄→等待→取退出码）**是** IDL 的起点，
> 落在病灶一侧。这条线是 ⑤ 的核心判定线。

### 1.3 表放载荷侧，答案可由平台侧提供（CO-RE 复核）

对 L3（布局），显式测两种形态并分别记录：
- **(a) 烘焙式**：布局数值（`104`）作为常量直接进表 —— 这是**生产者知道布局**，即 ANDF/Bitcode
  的失败根因（表跟着某个目标做完一半）。
- **(b) 查询式（CO-RE）**：表只写「STARTUPINFOA 的 cb 字段偏移」这个**名字**，由**宿主侧布局神谕**
  在降级/绑定时回答并常量折叠进指令流。载荷携带查询，宿主携带答案。

**判据 ⑤ 必须回答**：L3 表不出来，是「表的表达力不够」，还是「缺一个提问通道（第五类原语
Declare，R1 §10.5）」？两者是**完全不同的判决**。

### 1.4 不许开逃生舱口

编组器不得含形如「若 intent==SpawnWait 则走手写路径」的旁路。真降不了就**如实记为降不了**，
不要用一个特判把结论做好看。

## 4. 判决树 + kill criterion + 时间盒

**事前写死。判决树按性质排序（斜率 ② 优先于截距 ③），与 §3 对账。**

```
1. 主判据 = ②（斜率）。若在【单次调用族】里加一个 intent 或加一个目标仍需写编组器代码
   → Q7 判负（「只是把代码改了形状」），不看其它。
2. ② 在单次调用族成立（代码增量=0，全在数据）→ 看 ①：逐类泄漏能/不能/部分，给出边界。
3. ①②给出边界后 → ⑤ 是主产出：把「表驱动失效处」列成清单，并对 L3 判定
   「不可表驱动」 vs 「需第五类原语（查询通道）」。
4. ③④ 是量化旁证：③ 说通用编组器这笔固定成本多大；④ 说收窄了多少信任洞。

kill criterion（布尔门 ①）：若 L1 或 L2（最简单的两类泄漏）都表不成数据
   → 命题证伪，立即停，写结论。
时间盒：做到 ①–⑤ 对【单次调用族】出数 + 对【SpawnWait】完成边界分析为止。
   在此之前：不做第二个 ISA、不做优化、不做 IDL/调用时序 bytecode、不实现完整的 Declare 原语
   （只用一个最小布局神谕来*检验* §1.3(b) 的重构是否成立）。
```

**与 §3 对账**（skill §3 强制）：①②③④⑤ 五个判据，判决树节点覆盖 ②（步1-2）、①（步2）、
⑤（步3）、③④（步4）；① 亦是 kill 门。无遗漏项。分支顺序 == 性质优先级（斜率②→清单①⑤→截距③④）。

### 失败模式（挑相关的）

- **滑向 IDL**：见 §1.2。判据 ⑤ 把「调用时序/控制流」显式划到病灶侧，防止用一个 bytecode 硬撑「全可表」。
- **测了个双胞胎**：编组器对两目标必须是同一份代码；若两目标偷偷各留一段专属 emit，② 就被抹平。
  §1.1 判定式（无 `match intent`）防这个。
- **只做一个点**：② 要求 ≥2 点。单次调用族已有 5 个形状各异的 intent（不同 arity/出参/常量），
  天然是多点；加目标有 SysV/Win64 两点。
- **越做越大覆盖长尾**：⑤ 要求量到失效处而非覆盖三载荷。宁可「子集内成立」的有边界结论。

## 7. 本实验**不**回答

- **第五类原语 Declare 该不该进架构**：⑤ 若判「L3a 需查询通道」，那是 Q8 候选，本实验只给证据。
- **布局神谕从哪来**（目标是否发布 BTF 等价物）：R1 已指出「若目标无机器可读类型描述，载荷只能猜」。
  本实验用一个手填的最小神谕**假设它存在**来检验重构，不解决它的来源。
- **降级器放核内还是核外**（TCB 权衡）：③ 给编组器大小数据，不替它做决定。
- **可验证性做成不变量**：Q4 已做中立核那半；④ 只量「表比代码多可验多少」，不重做 Q4。

## 8. 实验结论回填（2026-08-08，实测）

实现落在 `research/dynamic-core/tables/`（独立 `rustc`，不挂根 workspace）；完整数字、边界清单、
复跑命令见该目录 `RESULTS.md`。以下是回填要点。

### 判决：**有边界可达（bounded reachable）**

缝**收窄但不闭合**。表驱动在**单次原生调用族**（Alloc/FileOpen/FileRead/FileClose/WriteStdout）
上**完全成立且实测跑通**（pure→163，rhp→`a49d2cbecc13994f`，全部由数据经一个固定编组器降级）；
在**编排/控制流**与**跨 ISA 重构**上**不成立**，硬撑就是发明 IDL（本实验要检测的病）。

### 逐判据（主判据 ② 先行）

- **② 增长曲线（主判据，PASS on family）**：单次调用族里 **+1 intent = 0 编组器代码**、
  **+1 同-ISA 目标 = 0 编组器代码**，增量全在数据。结构性证据：编组器 `grep -c 'match intent'`=0
  （仅文档注释）、`grep -c 'abi.name =='`=0，目标行为只经数据字段（`arg_regs`/`shadow`/`reach`/`table`）选择。
  win64 与 sysv64 共享 100% 编组器。**在 I2（跨 ISA 重构）与编排 intent 上 ② 判负**（仍需代码）。
- **① 表达力布尔门**：L1(换号)/L2/L4 = 数据且**执行通过** → kill 门未触发。L3 **拆开**：
  L3a 布局 = 数据但**仅查询式（需宿主神谕）**；L3b 编排 = 代码。L5 = 部分（记录哨兵是数据，*据此分支*是代码）。
- **③ 代价**：固定编组器 ~70 行（单次调用核）/ ~112 行（含 L3a），一次性、服务所有 intent×同-ISA 目标；
  对照 Q1 的 **OS 接口内容 ~90–110 行/目标且随 intent 增长**。发射字节 ≤ Q1（pure 逐字节相同；
  rhp SysV 1046 相同、Win64 1216 比 Q1 少 33 字节，因 WriteStdout 改单调用）。
- **④ 可验证性增益**：schema 校验器（41 行）实测两目标各 5 行 0 错、负样本被拒（非空洞）。
  它能查 Q1 手写代码无法查的**配方良构性**（reach 索引/参数引用/出参宽度/结构体偏移越界），把 Q4 的
  file-I/O intent 区从「不透明字节」重分类为「经校验配方生成的字节」。**但查不了 L1 命名真值**
  （符号索引 1 是否真的是 CreateFileA）——收窄结构洞，未收窄绑定洞。
- **⑤ 边界（主产出）**：表驱动失效于 **L3b 编排/控制流**（多调用数据流、SysV fork/分支）与
  **I2 跨 ISA 重构**（`openat`/`clone`：系统调用*集合*改形，非改号），外加 varargs、回调、ioctl 长尾。
  **维度修正（Q5）**：缝不是一张扁平的 per-target 表——**布局=per-OS、reach=per-(ISA,OS)、ABI=per-ISA**。

### L3 能否表驱动（对编排者 CO-RE/Declare 重构的回答）

**L3 拆成两半，答案相反**：**L3a 布局**能表化，但**需一个查询通道 + 宿主布局神谕 = 第五类原语 Declare**
（R1 §10.5 得到实证）——不是载荷侧纯数据。**L3b 编排**不能，且**没有任何原语能补**——它是控制流，
是这个架构的**永久残留**。所以「L3 不可表驱动」是错的读法；正确的是「**L3 布局需 Declare；L3 编排是控制流，缝在此永不闭合**」。

### 缝被收窄了多少

- **收窄**：单次原生调用的 OS 内容（L1 换号/L2/L4/L3a 布局）从「每目标手写代码、O(目标×intent)」变成
  「固定编组器 + 数据行」，且数据可 schema 校验——正是 Q1/Q4 判为不可验的那 ~30–41% file-I/O intent 区，
  现获得输入校验锚点。
- **未收窄（永久残留）**：控制流编排（L3b，Q4 的 ~45–56% spawn 区）+ 跨 ISA 重构（I2）+ L1 命名绑定真值。
  **这意味着这条缝的控制流部分是本架构的永久特征，应写进设计而非继续找解法。**

### 推翻预期之处

- 预期「L3 结构体布局不可表驱动」；实测**布局可表驱动（查询式）**，不可表驱动的是**编排/控制流**——
  难点从「布局」移到了「时序与分支」。这与 Q5「L3 是 ISA 无关的 per-OS 事实」一致：布局是有界的，会动的是控制流。
- 预期 WriteStdout 属单次调用族；实测 Win64 它本是 2 调用（GetStdHandle+WriteFile），须把句柄获取推到绑定期
  （ctx[2]）才保持单调用——**单次调用可表化有时以「把句柄获取重定位到绑定」为代价**，是 Q1 封装重定位的温和变体。

### 规格 bug / 遗漏

- 无判决树漏项（①–⑤ 均为节点，②→①⑤→③④ 按性质排序，与 §3 一致）。
- 规格 §2 只做单 ISA，故 I2 只分析不执行——已在 §7「不回答」隐含，RESULTS 偏差 #4 明记。

*研究轨投影。不承诺版本归属，不改 PRD 能力状态。*
