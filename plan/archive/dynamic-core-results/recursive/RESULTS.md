# Q17 RESULTS — 递归 / 自托管边界（Windows/x86_64，实测）

**这是"找解法"实验。** 全轨最强收敛：所有残留都停在同一条 intent 边界（Q1 中立性破裂 / Q4 结构守卫停下 /
Q15 执行时控制归零）。候选解法：如果 intent 另一侧的东西**本身也是跑在另一个核实例上的中立 IR**，观测/验证/策略
是否在边界另一侧重新成立？**判据在写码前由委托方钉死（①②③④⑤），事后未改。主判据 ②。**

## 判决 — **部分解法：缝没变小，但 A 面对的那道缝从"不透明"换成了"可检查的中立 IR"**

一句话：**递归不缩小 intent 边界的缝，也不消灭它——它把 OS 内容缝（L2–L5）原封搬进 B，还净增一道 A↔B 信道缝；
真正的所得是 A 与子任务之间那道墙从"不透明外来命令"变成"可检查、可结构验证的中立 IR + 可协作的结构化回报"。**

- **① 布尔门 PASS**：核 A 通过真实进程边界（`CreateProcessA`）启动核 B（我们自己解释器的另一实例）跑一段中立 IR。
  A 能观测/约束 B——逐项吊打 Q15 的"零观测"：**产出前**看到完整 IR（14 ops / intents=`{Alloc,WriteStdout}`）、
  **运行时**拿到逐 intent 轨迹（`Alloc(18)→ptr`、`WriteStdout(ptr,18)→18`）、**捕获 B 的 stdout**（`"hello from core B"`）、
  拿到结果。且能约束：A 产出前扫 IR 见 `SpawnWait` 即拒；即便放行，B 用同一个 O(1) chokepoint 运行时 deny。
- **② 缝移动到哪（主产出）**：见下。**诚实结论：新缝不比原缝小。** OS 内容缝（L2–L5）没缩小，只是搬进 B；
  A↔B 信道是**净新增**的一道缝（固定编解码 + 中立词表）。缝**换了性质**（可观测），但没**变小**。
- **③ 适用边界**：外来二进制（cmd.exe）、已有原生库、任何"另一侧不是我们的 IR"——**递归完全不适用**。
- **④ 成本**：每层一个**完整解释器进程** + 一次编组往返。实测 in-process 1.2 µs → 跨 A→B 边界 **~11.4 ms**（≈9000×）。
  **字节便宜（模块 210–286 B），延迟昂贵。**

**净判决落在委托方给的三档里**：不是"解法（缝变小）"，也不是纯"搬家（缝不变）"，是**部分**——
**对自托管 IR：A 面对的边界从不透明转为协作式可观测（真实收益）；对外来二进制：完全不适用。**
而"缝变小"这个主判据的诚实答案是 **NO**：OS 内容缝原样存在（搬进 B），全局机器只增不减。

## ① 布尔门 + 逐项对照 Q15（PASS）

`driver.exe` §①。核 A 启动核 B 跑 `sub_write`（中立 IR：Alloc 一段缓冲、拷入消息、WriteStdout、返回长度）。

**观测对照（逐项 vs Q15 的"只拿回退出码"）：**

| 能力 | Q15 外来 spawn（cmd.exe） | Q17 递归（核 B 跑中立 IR） |
|---|---|---|
| 任务在启动前可检查 | **否**（命令不是 IR 值） | **是**（子任务就是 IR 值，A 手里握着） |
| 启动前已知会调哪些 intent | 否 | **是**（`{Alloc, WriteStdout}`） |
| 逐 intent 运行时轨迹（args+ret） | 否 | **是**（`Alloc[12]→ptr`、`WriteStdout[ptr,12]→18`） |
| 副作用输出被捕获 | 否 | **是**（`"hello from core B"`） |
| 结果值 | 是（退出码 7） | 是（18） |
| 运行时 allow/deny intent | 仅启动时（放行后即盲） | **逐 intent，在 B 内部**（同 Q15 的 O(1) chokepoint） |
| **不信任被调方即可强制其诚实** | **否** | **否**（仍须信任 B 的解释器二进制） |

**约束实测**（`sub_evil` 伸手要 `SpawnWait`）：
- (a) A 产出前扫 IR 见 intents=`{SpawnWait}` → **启动前即拒**（`true`）。
- (b) 即便以策略 `{Alloc,WriteStdout}` 放行，B 运行时 **deny `SpawnWait`** 并上报。
- → Q15 的 intent chokepoint 现在**同时守住内层核**。

**布尔门成立**：机制存在，A 对 B 的观测/约束真实且远强于 Q15。但注意最后一行——**强制诚实仍不可得**（见 ②/⑤ 残留）。

## ② 缝移动到哪 + 新缝比原缝小吗（主判据）

`driver.exe` §②。**递归没有消除缝，它把缝拆成三段，只有一段是净新增的可观测缝。**

**下行线格式尺寸（子任务作为 IR 值穿过缝）：** `sub_compute` 210 B / `sub_write` 286 B / `sub_evil` 48 B，
`de(ser(m))` 逐一 round-trip 通过。

**新缝的精确解剖（对照原缝"OS 接口内容 L1–L5"）：**

| 缝的组成部分 | 是什么 | 比原缝小吗 |
|---|---|---|
| **启动半边** | `CreateProcessA` 起 B——**与 Q15 的 L1–L5 spawn 完全相同**，复用一次，O(1) | **不小**（是同一道 spawn 缝，只是只用一次） |
| **下行半边（A→B）** | 固定编解码；载的是**中立 IR**，A 产出前可检查/可结构验证（Q4 全适用） | **性质变了**：内容是可检查 IR，不是不透明命令。但这是**净新增**的一道缝 |
| **上行半边（B→A）** | 固定编解码；B 的结构化轨迹（中立 intent tag + 值 + 捕获输出） | 净新增，可观测 |
| **词表** | op tag 0..=12、intent tag 0..=5——各 **1 个中立字节，两核共享** | 对照 **Q1 L1**：per-target 符号串/号，**disjoint**。此处中立且共享——**这一项确实优于 L1** |
| **OS 内容（L2–L5）** | arity 注入、结构体布局（`STARTUPINFOA.cb=104`）、out-param 宽度、哨兵约定 | **完全没缩小**——**原封搬进 B**。B 真去开文件/spawn 时照样背这些 |

**主判据的诚实答案——"新缝比原缝小吗？NO。"**
- 全局看：你现在有 **同样大的 OS 内容缝（在 B 里）+ 一道净新增的 A↔B 信道缝**。总机器只增不减。
- 唯一真·改善：**L1（reach 命名）** 被中立化——A↔B 用共享中立 tag，替掉了 per-target disjoint 符号表；
  且 A 只需看见**中立 intent 词表**，不必知道该子任务 intent 的 L2–L5（那些 B 内部处理）。
- 换句话说：**A 侧看见的缝从"不透明墙（∞，零观测）"变成"可检查中立 IR + 协作回报"**——这是**可观测性轴**上的巨大改善，
  **不是 OS 内容轴上的缩小**。递归把缝**换了性质**（可检查），没**缩小**它。

> 这正是委托方预判的"缝可能只是移动而非消失"。**实测证实：移动 + 换性质，未缩小。** A↔B 那道进程/编组缝是真的新缝；
> 它可观测（固定编解码、中立词表、内容是可验 IR），但它**存在**，而且 OS 内容缝在 B 里丝毫未动。

## ③ 递归不适用的清单（和"适用"一样重要）

`driver.exe` §③：

- **外来二进制（cmd.exe）**：没有我们线格式的解析器。递给它 286 B 的 IR 什么都不会发生——**它不是我们的核**。
  → 另一侧**必须是我们自己的解释器二进制**，否则观测根本不可能。
- **已有原生库（经原语 ④ 调的 .dll/.so）**：同一堵墙——符号背后是原生码不是 IR，递归无法包住它。
- **任何"另一侧不是我们的 IR"的情况**：无法下行，谈不上"重新成立"。

**→ 递归买到的可观测性，只覆盖我们自己以中立 IR 产出的组件。** 这与 Q1/Q15 的 intent 边界完全同形：
边界只在通向**外来原生码**时存在；把核推过边界，只对**自产 IR** 有意义。

## ④ 一层递归的成本

`driver.exe` §④（`sub_write`，in-process `run_observed` vs 跨 A→B 边界，各自 reps 平均）：

| 度量 | 值 |
|---|---|
| 同一子任务，进程内（无边界） | **~1.2 µs** |
| 同一子任务，跨 A→B 边界 | **~11.4 ms**（≈**9000×**） |
| 下行模块字节 | 210–286 B |

- **delta = 每个被观测子任务一个完整解释器进程 + 一次编组往返。**
- **北极星问法**："让 agent 产出的一个子任务可观测要付多少？" 答：**~1 次进程 spawn（本机 ~11 ms）+ O(模块尺寸) 编组。**
  **字节便宜，延迟昂贵。** 粗粒度子任务（每个做很多活）分摊得起；细粒度（每条指令一层）绝无可能——那会是每指令一个进程。
- 未测/时间盒外：共享内存信道（可去掉文件往返，降延迟）、多层递归（A→B→C）、第二个 ISA。**一层足以回答 ①②③。**

## ⑤ 对 SYNTHESIS 的净影响（改法）

**目标**：⑤ 信任图里"intent 边界之外只能信"（5.1 表"intent 之外"行 + 收敛段 + 5.3 第 4 条）。
**改法**（SYNTHESIS.md 本轮确认 clean/未被占用，已按此施加一处 Q17 note，见提交）：

> **"边界之外只能信"有一个有边界的例外。** 当且仅当边界另一侧是**我们自己产出的中立 IR（跑在另一个核实例上）**时，
> 观测在另一侧**协作式**重新成立：A 可以 (a) **产出时结构验证**子任务 IR（Q4，不可遗忘），(b) 从 B 拿到**逐 intent 运行时轨迹**
> （B 自报、B 用同一个 O(1) chokepoint 自我管控）。残留信任从"信任整个不透明被调方"**收窄**到
> **"信任 B 的解释器二进制（Thompson/R3）+ 产出时验证 M_B"**。
> **但递归不缩小 OS 内容缝**——L2–L5 原封搬进 B，另加一道**净新增的 A↔B 信道缝**（固定编解码、中立词表；
> 其 L1 半边被中立化，优于 Q1 的 per-target disjoint 符号表）。
> **对外来二进制/原生库，"只能信"不变**（③）。
> **代价**：每层一个进程（~11 ms）。
> **故 intent 边界作为 OS 内容缝是真·永久残留（Q17 没缩小它，确认 R5 方向）；作为 A↔子任务的观测壁垒，
> 递归把它从不透明转成协作式可观测——但那是可观测性的改善，不是缝的缩小。**

**与 R5 的关系**：Q17 **加强**而非推翻 R5。R5 说"intent 之外零观测零约束"——那**对外来内容**仍然成立。
Q17 只在"另一侧是自托管 IR"这个**受限前提**下松动它，且松动的是**协作式**观测，不是**强制式**。
**结论**：不应继续在"缩小 intent 边界这道缝"上找解法（递归证明了这条路只搬家不缩小）；
**该接受这道缝，把外来内容的可观测性从 IR 之外（进程/OS 级观测）解决**——这与 SYNTHESIS 5.3 第 4 条一致，Q17 给它补了实测支点。

## 与预期不符 / 诚实条款

1. **委托方预期"新缝可能只是移动而非消失"——实测证实，且更精确：移动 + 换性质，未缩小。** 没有为了交出"解法"而美化：
   主判据 ② 的答案是**缝没变小**。递归的价值是**把 A 面对的边界变可检查**，这是真实的，但它**不是**"缝变小"。
2. **强制诚实仍不可得**（① 表最后一行）。A 能验证 B *被要求做什么*（产出时 Q4）、能收 B *自报* 它做了什么（协作式），
   但不能强迫一个恶意/被篡改的 B 诚实上报——那仍落回**信任 B 的解释器二进制**，即 R3 的 Thompson/内核残留。
   **这条不能被"递归=可观测"的读法盖过。**
3. **成本的形状是延迟而非字节**：9000× 是因为 in-process 太快（1.2 µs），进程 spawn ~11 ms 主导。字节侧（286 B）廉价。
   这决定了递归**只对粗粒度子任务可行**。
4. **B 的 seam 是安全子集**（Alloc+WriteStdout；File*/SpawnWait 门控关闭），因为一层实验不需要 B 真去开文件/起孙进程。
   门控本身**就是**约束结果（同 Q15 的 O(1) chokepoint），不是回避——`sub_evil` 的 deny 实测到了。
5. **`child.rs` 复算了 Q9 `eval_op` ~13 行**（Q9 的 `eval_op` 是私有 `fn`，无法从外部驱动以插入 intent 轨迹）。
   算术语义逐字相同；新增的只有 intent 记录 sink 与策略 chokepoint——即让 B 可观测的那部分。

## 独立参考值（证明不是自证）

- `sub_write` 捕获输出 = `"hello from core B\n"`（A 从 B 的上行 report 里读到，与 B 源码里的 rodata 逐字节相符）。
- `de(ser(m))` 对三个模块 round-trip 成功（block 数 / n_vals 相符）→ 线格式无损，A 手里的 IR 与 B 收到的是同一个。
- `sub_evil` 的 `denied = SpawnWait` → 约束 chokepoint 非空转。
