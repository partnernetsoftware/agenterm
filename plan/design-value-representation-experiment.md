## §0 背景与已定事项

`.qjs` 编译成 `.wasm`，产物自带运行时。M2「整数世界」看似不碰堆，但只要有
`function f(x) { return x; }`，`x` 就必须是**通用值表示**的一个值——M3 字符串到了，
`x` 可能是串。于是要么 M2 先用裸 i32 编、M3 全部重写，要么 M2 从第一天就用通用表示。
后者明显对，**前提是那时已知表示是什么**。所以这个决策卡在 M2 之前，不是 M3 之前。

**已经确定、不在本实验讨论范围内：**

1. 目标是 **wasm32**。指针天然 i32。
2. **无 JIT，不生成机器码。** tinyvm 产品定义，不动。
3. **不吃 WasmGC 提案。** tinyvm 核不支持，回收要自己做。
4. 产物是标准 `.wasm`，必须过 tinyvm 的严格装载门。
5. 运行时（分配器、串操作、堆）由编译器发射进产物，**也吃 `Limits`，也算体积**。
6. 语言覆盖面无原理排除，按真实脚本需求长（PRD 36）。
7. 首个能力锚点是 `fleet.js` 等价物（归档门第一条）。

**已核实的机制前提**（读过源码，不是印象）：

| 事实 | 依据 |
|------|------|
| `F64ReinterpretI64` / `I64ReinterpretF64` 存在并可执行 | `wasm.rs` opcode 0xBD / 0xBF，解码 2866-2869，执行 7199-7211 |
| multi-value 已支持 | tinyvm `prd/PRD.md` 能力树 `[x]`；双字可作两个返回值，不必绕内存 |
| `peak_activation_slots` = **locals + 操作数 + 控制帧**的峰值总和 | `wasm.rs` 8635-8639 |

第三条是本实验存在的核心理由：**双字每个值占 2 个槽，NaN-boxing 占 1**，而
`max_activation_slots` 是 tinyvm 的一个真实预算。这个差异 tinyvm 自己就会报数，
判据不需要另造尺子。

## §1 硬约束（违反则实验无效）

1. **一份实现，打包两次。** 词法/语法/AST/测试语料**完全共用**，只有值表示那一层有两个
   实现。写两个独立原型会引入「哪个花的时间多」这个混淆变量，且 90% 工作重复。
2. **两个变体跑同一份语料**，逐条比对结果。
3. **产物必须过 tinyvm 装载门并真实执行**。"我的编码器认为它对"不算证据。
4. **不做优化。** 两侧都是直白降级。任何一侧手工调优会污染斜率。
5. **不引入第三方 wasm 编码依赖。** 复用本仓已有的自研编码器。
6. 度量按 §3 的纪律，**每个数字第三方可复跑，命令写进 `RESULTS.md`**。

### 病灶探测器

> 任何为了让某个类型跑通、而在值表示**之外**开特例（"整数走快路径不装箱"、
> "字符串单独一条 ABI"、"给 IR 加一个逃生舱口"）的冲动，是本实验要**检测**的病，
> **不是**要满足的需求。真需要就**记为发现写进 §7 泄漏清单**，不要偷偷加。
>
> 理由：这类特例正是让一个值表示在纸面上"更快更小"、在真实语言长起来之后崩掉的机制。
> 一个表示法逼出多少特例，比它今天快多少更能预测三个里程碑之后的成本。

### 已知偏差（结论因此是上界，不是确值）

本实验里的字符串实现是**研究级最小版**，不是 M3 的真实字符串（无驻留表、无 8/16 位
双形态、无 GC）。因此 ③④⑤ 测出的斜率是**该表示法边际成本的下界估计**——真实 M3 只会
更贵。结论必须写成「在此子集内 A 的边际成本低于 B」，不得写成「A 的边际成本是 N」。

## §2 最小实验内容

| 维度 | 选了什么 | 为什么这样选 |
|------|----------|--------------|
| 变体 | **V1 双字** `(tag: i32, payload: i64)`；**V2 NaN-boxing** 单 `f64` | 这两个就是争议本身。QuickJS 按指针位宽在这两者间分岔，而 wasm32 的约束与它 32 位那侧不同（无 64 位指针压力），所以不能直接抄它的结论 |
| 增长轴上的点 | **P1 仅整数**；**P2 整数 + 字符串** | 斜率判据要求**至少两个点**，只做一个 = 零信息量。字符串是第一个堆类型，是"加一个类型"这个动作的最便宜代表 |
| 语料 | 一份共用 `.qjs` 程序集：算术、比较、函数调用与返回、条件、循环；P2 追加串字面量/拼接/长度/相等 | 覆盖**值穿过 ABI 边界**的每种路径（局部变量、参数、返回值、操作数栈），那才是表示法成本发生的地方 |
| 不做 | 对象、数组、闭包、回收、`fleet` 门 | 它们的成本由本实验的结论**塑形**，放进来会让实验变成 M3–M5 本身 |
| 构建 | 4 份产物：V1P1 / V1P2 / V2P1 / V2P2 | 斜率 = (P2 − P1)，每个变体一条 |

## §3 判据表与度量纪律

| # | 判据 | 性质 | 怎么量 |
|---|------|------|--------|
| ① | 语料全部结果正确，且产物过 tinyvm 装载门 | **布尔** | 同一份期望值表，两变体逐条比对；`Module::from_bytes_with` + `instantiate` + 真实调用 |
| ②a | **f64 语义保真（判决门）**：`-0` 与 `+0` 可区分、`±Infinity` 保真且可区分、NaN 存进去取出来仍是 NaN、任何值不被静默改判类型 | **布尔·安全** | 专项语料。这是 ECMA-262 6.1.6.1 要求的那一半 |
| ②b | **NaN payload 位级往返**（存进一个带 payload 的 NaN，取出来位完全相同） | **清单·非门** | 同一份语料。ECMA-262 6.1.6.1 注明 Number 类型只有**一个** NaN 值、脚本无法观测 payload，所以这是表示法的一个**性质**，不是合规要求：**上报，不判决** |
| ②c | **恶意位模式下不发生类型混淆**：一个落在装箱位空间里的真 NaN 不得被读成指针/别的类型 | **布尔·安全** | 同一份语料。这才是 ②原本那句话里真正的安全问题 |
| ③ | **Δsteps**：P2 − P1，按语料逐条与总计 | **斜率** | `Instance::last_steps()`（S5：原文写的 `Outcome::steps` 在 tinyvm 里不存在），确定性，无需计时 |
| ④ | **Δpeak_activation_slots**：P2 − P1 | **斜率** | `Instance::last_peak_activation_slots()`（同 S5）。双字每值占 2 槽是本实验最直接的预判 |
| ⑤ | **Δ发射字节**，**拆两栏**：共享运行时 / 每函数码 | **斜率** | 两栏含义相反：共享部分增长是一次性的，每函数增长会随脚本数放大 |
| ⑥ | 今日字节（截距），三档上报 | **截距** | 见下方口径 |
| ⑦ | **泄漏清单**：每一处该表示法逼出的特例、妥协、或"本来想加逃生舱口"的地方 | **清单** | 主产出之一。边界的形状比"能/不能"更值钱 |

**判据 ⑦ 可能比 ③④⑤ 更重要**：三个里程碑之后决定成本的是特例数量，不是今天的字节数。

> **修规格 S1（2026-08-24，实验执行中发现）。** ② 原文写的是「真 `NaN`（含 payload）…
> 存进值、取出来仍相等」，而「相等」对 NaN 没有定义清楚。按位相等读，V2 在判决树第 1 步
> 直接判负、实验就此结束；但 **ECMA-262 是本项目声明的语义权威**，它给 Number 类型只留
> 一个 NaN 值，payload 脚本不可观测。于是「按位保真」是**越过权威去加要求**，会用一条
> 非要求判死一个变体。故拆成 ②a（可观测语义，判决门）/ ②b（位级往返，只上报）/ ②c
> （类型混淆，判决门）。②c 是原句里真正藏着的安全问题，单列出来。

### 度量口径（照 §2.5，每个数字带标签）

- **体积三档**，缺哪档写「未测定」，不许用别档的数填：
  - **L1** 值表示机制码（纯表示层，不含语料函数、不含运行时数据）
  - **L2** L1 + 该变体跑通语料所必须的全部发射运行时
  - **L3** 整个 `.wasm` 产物字节（code+data，flat）
- **工具**：产物是 `.wasm`，按**段**统计（code section / data section / 总文件），
  工具与命令写进 `RESULTS.md`。**禁止跨口径相除。**
- **执行状态**逐行标注：`真机执行` / `仅字节测量`。本实验所有产物**必须真机执行**，
  未执行的数不得进结论表。
- **LOC** 统一「非空非注释行」，命令写出。比较两变体 LOC 前声明两者能力集相同。
- **倍数**：基线内联写出，不跨口径相除。

## §4 判决树 · kill criterion · 时间盒

**对账（照 §3 逐项点名，不漏）**：① 布尔门 → 在树的第 0 步。②a / ②c 布尔·安全 → 第 1 步；
②b 不进树，只在 §8 上报（S1）。③④ 斜率 → 第 2、3 步。⑤ 斜率 → 第 4 步。
⑥ 字节截距与 ④ 截距 → 第 5 步并列复核（最低优先级，性质使然；S3）。
⑦ 清单 → 不是判决节点，是**并列主产出**，在 §8 全文记录；它不参与排序是因为清单没有
大小关系，但它可以**推翻**一个已胜出的变体——若胜方的泄漏清单里出现「必须给 IR 开逃生
舱口」，按 §1 病灶探测器，那是**判负条件**，见第 0 步。

```
0. kill criterion（任一触发即停）：
   - 某变体 ① 不过（结果错 / 过不了装载门）→ 该变体判负，不再量它。
   - 两变体 ① 都不过 → 命题证伪（「通用值表示能以可接受成本降到 MVP wasm」不成立），
     立即停，写结论，去重新想 M2 的形状。
   - 某变体的 ⑦ 泄漏清单出现「必须在值表示之外开特例才能跑通」→ 该变体判负，
     哪怕它 ③④⑤ 全赢。理由见 §1 病灶探测器。

1. ②a 或 ②c 不过 → 该变体判负。②b 只记录，不参与判决（见 S1）。
   （预判 V2 在这里有风险；若它反而通过，那是本实验最值钱的发现之一，§8 点名。）

2. 主判据 = ④ Δactivation_slots。若一方 Δ 明显更小（差距 > 20%）→ 判它胜，进第 5 步复核。
   理由：`max_activation_slots` 是 tinyvm 的真实预算，槽位斜率直接决定"一个脚本能有多深"。

3. ④ 打平（差距 ≤ 20%）→ 看 ③ Δsteps。差距 > 20% 者胜，**进第 5 步复核**。

4. ③ 也打平 → 看 ⑤，且**只看「每函数码」那一栏**（共享运行时是一次性的，
   随脚本数放大的才是长期成本）。有胜者同样**进第 5 步复核**。

5. **复核（不可推翻）**：并列上报两个截距——⑥ 字节截距，与 ④ 截距（绝对 peak
   activation slots）。二者性质相同（都是截距），按 §4 对账已定的理由都排在最低优先级，
   **只能佐证或记录分歧，不能推翻第 2/3/4 步已出的胜负**。
   若第 2/3/4 步全部打平才落到这里定胜负：先看 ⑥ 截距；再打平则偏好 **V1 双字**，理由是
   可调试性与不与 f64 语义纠缠——这是一个**明示的平局默认**，不是论证结果。

> **修规格 S2（2026-08-24）。** 原树第 2 步写「判它胜，进第 5 步复核」，但第 3、4 步
> 没写胜出之后去哪，一个在第 3 步分出的胜负在树上无后继。已补：2/3/4 步的胜者一律进
> 第 5 步复核，且复核不可推翻。
>
> **修规格 S3（2026-08-24）。** §0 论证 `max_activation_slots` 是真实预算、并把它当作
> 本实验存在的核心理由，但树只判 ④ 的**斜率**；而预算是按**绝对值**执行的，斜率单独
> 回答不了「一个脚本能有多深」。已补：第 5 步与 ⑥ 并列上报 ④ 截距。本次实验里两个截距
> **指向相反**，这正是该修补要让它可见而不是隐形的情形。

kill criterion 已在第 0 步。
时间盒：做到 ④ 出数为止。在此之前不做优化、不做第三变体、不碰对象/闭包/回收、
        不开 M2。④ 出数后若判决未定，继续走树，仍不做上述任何一项。
```

「共用 lex/parse/AST/encode **从编译器复用，不复制**」是 §1 约束 1 的落地方式：
复制会让两边漂移，而漂移正好污染我们要量的东西。

> **修规格 S4（2026-08-24，实测后）。** 这条对**今天的** `tinyvm-qjs` **不可满足**，
> 已实测不是印象：把它的 `lex.rs` / `diag.rs` 用 `#[path]` 收进外部 crate **能编过**，
> 但语料要的 `function` / `{}` / `return` / `while` / `=` / `==` / `<` / 串字面量
> **全部**被词法器判成 `Unsupported`；`parse`/`ast`/`emit` 更窄（单表达式、只有 i32、
> 无函数无控制流），`encode` 没有 memory/global/data 段、没有 i64/f64/控制流 opcode。
> 逐条证据见 `research/value-representation/RESULTS.md` 偏差 D1。
> 该条的**目的**（防两个变体漂移）在本实验里由「两变体同处一个 crate、共用同一份前端」
> 结构性保证，所以实验有效性不受影响；受影响的只是本 crate 与 `tinyvm-qjs` 之间的漂移，
> 对一次性研究 crate 可接受。**这是一个要上报的发现，本实验不改编译器。**

## §6 已排除的选项

| 选项 | 为什么排除 |
|------|-----------|
| 直接抄 QuickJS 的按位宽分岔结论 | 它 32 位那侧选 NaN-boxing 是被"想要 8 字节值"驱动的；wasm32 没有 64 位指针压力，驱动力不同，结论不可搬运 |
| 用 WasmGC 的引用类型 | tinyvm 核不吃该提案（§0.3） |
| 每个类型一套独立 ABI（不做通用表示） | 那是 M2 用裸 i32 的路，M3 全部重写；本实验存在的前提就是排除它 |
| 装箱一切（每个值都上堆） | 整数运算退化成分配，代价明显不可接受，无需实测 |
| 先做 M2 再回头改 | 见 §0：函数 ABI 会全部重写 |

## §7 本实验不回答什么

以下每一条都是下一个实验的候选：

1. **属性查找**：shape / 隐藏类 vs hashmap（M4）。由本实验结论塑形。
2. **回收策略**：bump + 整体丢弃 vs 引用计数 vs 标记清扫（M4–M5）。
3. **字符串真实形态**：驻留表、8/16 位双形态、相等性快路径（M3）。
4. **闭包环境的堆布局**（M5），以及它与 `eval` 词法作用域的共用机制。
5. **运行时怎么交付**：编译器发射 vs 预编译 blob 链入 vs 用 `.qjs` 自举。
6. 整数快路径是否值得——**故意不问**，因为问了就会诱发 §1 的病。若泄漏清单显示它是必需的，
   那本身就是结论。

### 8.1 判决路径逐步 trace

**第 0 步 · kill criterion。**
① 两变体全过：4 份构建 × 语料共 28 次真机执行，全部过 `Module::from_bytes_with`
+ `instantiate` + `invoke_by_name`，全部命中同一份期望值表（数字按位比较，`-0` 不满足
`+0`）。另加第三方复核：36 份产物在 `wasmparser` 0.239 下（只开 MVP + multi-value +
floats）全部通过——「我的编码器认为它对」和「我自己的 VM 收了」都不算证据，所以两样都
不单独用。命题未被证伪。⑦ 两侧泄漏清单**都没有**「必须在值表示之外开特例才能跑通」这一
条（§8.4）。→ 不停，继续。

**第 1 步 · ②。** ②a 两侧全过，②c 两侧全过。②b：V1 位级精确往返，V2 丢 NaN payload
——按 S1 只上报不判决。→ 不停，继续。

**第 2 步 · ④ Δpeak_activation_slots（主判据）。**
同语料读法（同样 5 个 A 组程序在两点各编一次）：V1 **0**、V2 **0**。
全语料读法：V1 **95**、V2 **84**，V2 低 11.6%（基线 V1 = 95），在 ≤ 20% 平局带内。
→ **打平**，进第 3 步。

**第 3 步 · ③ Δsteps。**
同语料：V1 **2 619**、V2 **4 365**，V2 高 66.7%（基线 V1）。
全语料：V1 **4 502**、V2 **6 482**，V2 高 44.0%（基线 V1）。
两种读法同向且都远超 20%。→ **V1 胜**，进第 5 步复核（按 S2）。

**第 5 步 · 截距复核（不可推翻）。**
⑥ 字节截距：V1 在两个点的 L1/L2/L3 **全部**更小，且把「64 位常量 LEB128 编码」这个
混淆变量用反事实扣掉之后**排序不翻转**（P1：V1 2 058 B vs V2 2 394 B）。→ 佐证 V1。
④ 截距（S3 新增）：V1 在 P1 多用 37.0% 槽（126 vs 92，基线 V2）、P2 多 25.6%
（221 vs 176）。→ 利 V2。
两个截距**指向相反**，且按树自身的理由都是最低优先级证据，不可推翻第 3 步。
→ **判决维持：V1。**

**⑦ · 并列主产出，可推翻胜者。** V1 清单里没有「必须在值表示之外开特例」条目；唯一一条
硬依赖是 multi-value 返回，tinyvm 今天就有，而且是**实测**的（见 §8.4 L1.1）。不构成
判负条件。→ **判决最终：V1。**

**稳健性复核（灵敏度 S-ADD）。** 第 3 步的整个 Δsteps 来自一个降级选择：P2 的 `__add`
把「是不是串」测在数字路径**前面**，于是每次数字加法都要付新类型的测试。把这个顺序对
**两侧同时**翻过来重测：③ 两侧都变成 **0**（打平）→ 第 4 步 ⑤「每函数码」两侧也都是
**0**（打平）→ 第 5 步 ⑥ 截距 V1 全面更小。**换一条路，同一个判决。**

### 8.2 数字表（判据 × 变体，带单位与口径）

口径定义写在 `RESULTS.md` §1，此处标签与那里一一对应；**不跨口径相除**，比值一律内联
写出基线。所有行**真机执行**，无「仅字节测量」行。

| 判据 | 口径 | V1 双字 | V2 NaN-boxing | 判决贡献 |
|---|---|---|---|---|
| ① 正确 + 装载门 | 28 次真机执行 / 36 份产物二次校验 | 全过 | 全过 | 都不判负 |
| ②a 可观测语义 | 7 个 f64 输入 × `-(-x)` 探针 | 过 | 过 | 都不判负 |
| ②b payload 位往返 | 同上（只上报） | 精确 | **丢失** | 不参与判决（S1） |
| ②c 类型混淆 | 7 个输入 × `x == x` 探针 | 过 | 过（靠强制规范化） | 都不判负 |
| ③ Δsteps 同语料 | `last_steps()` 求和，P2−P1 | **2 619** | 4 365（+66.7%，基线 V1） | **V1 胜（第 3 步）** |
| ③ Δsteps 全语料 | 同上 | **4 502** | 6 482（+44.0%） | 同向 |
| ④ Δ槽 同语料 | `last_peak_activation_slots()` 求和，P2−P1 | 0 | 0 | 打平 |
| ④ Δ槽 全语料 | 同上 | 95 | **84**（−11.6%，基线 V1） | 打平（≤20%） |
| ⑤ Δ共享运行时 | 单模块 code 段整条目 + memory/global 段，B | **+419** | +647 | 第 4 步未用到 |
| ⑤ Δ每函数码 | A 组 5 程序 code 段整条目，B | 0 | 0 | 打平 |
| ⑥ L1 截距 P1 | 表示层指令编码字节 | **2 230** | 4 368（+95.9%，基线 V1） | 佐证 V1 |
| ⑥ L2 截距 P1 | L1 + 必需运行时 + 堆声明 | **2 760** | 4 913 | 佐证 V1 |

| ④ 截距 P1 / P2 | 绝对峰值槽求和 | 126 / 221 | **92 / 176** | 利 V2（S3 复核，不可推翻） |

**斜率为什么不同——逐指令对得上，不是故事。** P2 的 `__add` 多出的类型测试，V1 每次调用
执行 **9** 条指令，V2 **15** 条；每个 A 组程序的 Δsteps 恰好等于该数乘以 `__add` 调用次数
（arith 1、compare 2、loop 40、call 232、mixed 16 —— 9×/15× 全部精确吻合）。根因：V1 的
tag 自己占一个机器字，测一次是一条比较；V2 的 tag 压在 double 里，必须先 reinterpret、
再 mask、再比。**语言每多一个类型，每个派发点每次调用就多一次类型测试，而 NaN-boxing 的
一次测试是双字的两倍。** 这条比字节数走得远：它预言的是 M4 对象、M5 闭包，不只是 M3 串。

### 8.3 与规格不符之处（逐条，包括让结论难看的）

完整八条见 `RESULTS.md` §7，此处点名对结论有影响的：

- **D1 前端没能「从编译器复用」，是本 crate 自己写的。** 已实测原因，见 S4 与
  `RESULTS.md` D1。**这是要上报给编译器的发现，本实验没改 `tinyvm-qjs` 一行。**
  对被测轴无影响：§5 那条防的是两个变体漂移，而本实验两变体同 crate 共用同一份前端，
  结构上不可能漂移。
- **D2 数字类型是 IEEE-754 double，不是 i32——这条让胜者好看，必须点名。** §2 写 P1
  「仅整数」，这里读成「语料只用整数值的 Number」，类型仍按 ECMA-262 是 double，因为
  ② 要求表示法必须装得下真 double。代价：V2 因此要在**每个**装箱的算术结果上付
  NaN 规范化；换成 i32 数字类型它只需一条 `i64.or`。量化：`loop` 在 P1，V2 比 V1 多
  203 步，其中 160 步（40 次装箱 × 4 条指令）是规范化，约 79%。**所以「绝对 steps 截距」
  这一项，换成整数类型设计有可能反号。** 但它翻不了 ③：规范化在 P1 和 P2 都在，**在差
  里被减掉了**，同语料 Δsteps 已逐指令归因给类型测试本身（§8.2）。
- **D4 每个运算符都是运行时调用，没有内联。** 无优化器编译器的直白降级、两侧同形，但
  它**低估**了 V1 的每函数码优势、**高估**了 V1 付的调用 ABI 成本。未量化。
- **D6 中途发现并修掉一个偏袒 V1 的公平性 bug，照实披露。** 初版给 V2 在**每个**函数
  （含从不装箱数字的语料函数）都预留了规范化用的 f64 scratch 局部，正好虚增本实验最吃劲
  的 ④。已在取数前修掉。修完 V2 在 P1 的峰值槽从 111 降到 92，**把 V2 对 V1 的 ④ 截距
  优势从 13.5% 拉大到 37.0%**——这个修法帮的是败方，照样修。
- **D7 引入了第三方 wasm 校验器（dev-only）**。§1.5 禁的是第三方**编码器**；`wasmparser`
  在这里是**校验器**，用法与 tinyvm 自家测试用 `wat` 相同，且永不进运行期依赖。按约束
  本意读作合规，若有异议在此点名。
- 另有 D3（②的专项语料是两个由宿主传参驱动的 `.qjs` 探针——`0xfff800000000000a` 没法写成
  JS 字面量）、D5（每点整套运行时全发，含未调用的）、D8（未测项：墙钟时间、堆高水位、
  P2 之后的任何点）。

规格自身的 bug 已就地修掉五处：**S1**（② 判据歧义，拆成 ②a/②b/②c）、**S2**（判决树第
3、4 步无后继）、**S3**（§0 讲绝对预算、树只判斜率）、**S4**（§5「从编译器复用」今天
不可满足）、**S5**（③④ 点名的 `Outcome::steps` 在 tinyvm 里不存在，实为
`Instance::last_steps()`）。理由逐条写在各自出现的位置，不静默改写。

### 8.4 泄漏清单摘要（判据 ⑦，并列主产出）

全表在 `RESULTS.md` §6。**两侧都没有**「这个变体只有破坏表示法才能跑通」这一条，所以 ⑦
没有推翻任何一方——**本简报点名说这条最可能定胜负，结果它没有，定胜负的是数字。**

- **V1**：L1.1 multi-value 返回是承重的（**实测**：关掉 multi-value，V1 产物被
  `wasmparser` 拒、V2 产物通过。tinyvm 有，所以不是判负条件；换一个没有 multi-value 的
  目标就会变成「必须经内存返回」的逃生舱口，那才是判负条件）；L1.2 每次读变量两条
  `local.get`；L1.3 `select` 选不了整个 JS 值（语料未触发，记为未验风险）；L1.4 装箱不
  需要 scratch 局部。
- **V2**：L2.1 每个装箱 double 必须规范化，不是可选项（②c 已测：不规范化时
  `0xfff800000000000a` 会被读成「地址 10 处的字符串」）；L2.2 根本装不下 NaN payload，
  因此不能兼作通用 64 位值载体；L2.3 payload 只有 48 位；L2.4 每个装箱数字的函数都要一个
  scratch f64 局部——**这正是 V2 的槽优势远小于「一字对两字」预期的原因之一**；
  **L2.5 冲动：在编译期已知不可能是 NaN 的地方跳过规范化（`__len`）——已探测，未实施**；
  **L2.6 冲动：给字符串开一条不装箱的快路径——已探测，未实施**（这正是 §1 病灶探测器
  点名的那种特例，实现 P2 时独立地撞上了）；L2.7 冲动：把 64 位 tag 常量提到 global——
  已探测未实施（属优化，§1.4 禁），改为在 `RESULTS.md` 用反事实列量化。

### 8.5 诚实条款

本节每个数字都由 `./measure.sh` 在 `RESULTS.md` §1 记的日期与机器上产出，来自**过了
tinyvm 装载门、被第二个校验器独立复核过、并且真的执行过**的产物。没有估算、没有外推、
没有沿用上一次跑的数。

三处**削弱**本结论的地方，一处都没藏：D2（数字类型的选择，可能反号的是绝对 steps 截距，
不是定胜负的斜率）、⑥ 的 L1 常量混淆（V2 的原始体积差大部分是 LEB128 编码而不是机制）、
以及 ④ 截距（V2 明确赢的唯一一项，恰好是 §0 原本以为会定胜负的那一项）。

**结论是上界不是确值。** 串实现是规格规定的研究级最小版（无驻留表、无 8/16 位双形态、
无 GC），所以量出来的边际成本是真实 M3 的**下界**。每个 Δ 的正确读法是「**在此子集内**
V1 增加一个类型的边际成本低于 V2」，不是「V1 的边际成本是 N」。

### 8.6 推翻预期的地方（逐条点名）

1. **NaN-boxing 更大，不是更小。** §2 表里写它「省内存、省拷贝」，实现设计 §7 也这么记。
   实测 P1：L1 多 95.9%、整文件多 57.9%（基线 V1）。把常量编码这个混淆变量扣掉仍然更大。
   在 32 位目标 + LEB128 立即数下，把 tag 压进 double 是**花代码去买数据**，而语料里同时
   存活的值根本不够多到让那点数据省出来。
2. **NaN-boxing 更慢，不是更快。** 截距 +13.4% steps、斜率 +66.7%（均基线 V1）。
3. **④ ——§0 拿来立整个实验的那条判据——在最锐利的读法下打平在 0。** 「双字每值占 2 槽」
   预判的 2× 一处也没出现：P1 实测只多 37%。两个机制把差抵掉了大半：
   `peak_activation_slots` 同时数控制帧和固定类型的运行时局部，而 V2 的强制规范化 scratch
   （L2.4）又把省下的那个字加了回去。递归 `fib` 里 V1 的帧是 2 参数字 + 0 scratch、
   V2 是 1 参数字 + 1 scratch，**一模一样**。
4. **槽预算根本不是约束。** 实测每帧约 3.4 槽（V1，`call`：深度 14 用 48 槽），
   `max_call_depth` = 512 时约用 1 750 槽，是默认 `max_activation_slots` = 1 048 576 的
   0.2%。§0 那句「槽位斜率直接决定一个脚本能有多深」，对这种形状的帧不成立。
5. **V2 过了 ②。** 规格预判它在这里有风险，并说「若它反而通过，那是最值钱的发现之一」。
   它过了 ②a 与 ②c——但**只因为规范化是强制的**，而且**只在 ② 的措辞被改回 ECMA-262
   真正要求的那半之后**（S1）。按原措辞，V2 会在第 1 步上被一条非要求判死。
6. **病灶探测器响了两次，都在 V2，而且两次都拒得掉。** L2.5 与 L2.6 是实现过程中真实
   冒出来的冲动，不是假想；两条都没实施，实验照跑。所以 ⑦ 对两侧都没产出判负条件。

### 8.7 对下游的直接影响

- **M2 可以开工了**：函数 ABI 定为「一个 JS 值 = 两个 wasm 值 `(tag: i32, payload: i64)`」，
  参数逐值展开成两个，返回值用 multi-value 两个。
- **`tinyvm-qjs` 的一个缺口要补**（D1 / S4，本实验不动它）：前端只到单表达式整数，
  编码器没有 memory / global / data 段与 i64 / f64 / 控制流 opcode。M2 无论选哪个表示法
  都要先补这些。
- **没测、但如果单字槽优势将来变成约束就该测的**：JavaScriptCore 式的 double 偏移
  （存 `bits + 2^49`，让每个 double 含 NaN payload 都落在指针区之外），单字且 ②b 精确。
  §4 时间盒禁第三变体，所以本次没做——**要做就做它，不是本次这版 V2。**
